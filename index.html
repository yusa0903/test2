git push 後の公開手順ガイド

git push はコードをリポジトリに置くだけで、閲覧者向けの公開にはなりません。push の後に、ホスティングの設定と公開URLの共有が必要です。

公開方法の選び方

サイトの種類公開方法
静的サイト（HTML/CSS/JS）GitHub Pages など
サーバー処理・DBありVPS等のサーバーで git pull、または自動デプロイ

GitHub Pages で公開する手順

  1. トップページのファイル名を index.html にして push する。
    git add .
git commit -m "first release"
git push origin main
  2. リポジトリの Settings → Pages を開く。
  3. Source を「Deploy from a branch」、Branch を main、Folder を /(root) にして Save する。
  4. ビルドが必要な場合（Vite等）は、GitHub Actions で main への push 時に自動ビルド・公開する。Actions の緑チェック=成功、黄=実行中、赤=失敗。
  5. 公開URL https://<ユーザー名>.github.io/<リポジトリ名>/ を開いて確認する。
  6. スマホやプライベートウィンドウで表示確認する。
    • https で表示される
    • CSS・画像が反映されている
    • リンクが動く
    • 個人情報が載っていない
  7. URLを共有する。更新は修正して push するだけ。反映に1〜2分かかり、古い表示は Ctrl/Cmd + Shift + R で確認する。

自前サーバーで公開する場合

  • サーバー上で git pull origin main を実行する。
  • push で自動反映するなら、bare リポジトリ＋post-receive フック、または GitHub Actions から SSH でデプロイする。
  • 公開ディレクトリに .git が含まれると履歴を取得されるおそれがある。ドキュメントルートを public サブフォルダにするか、ドットファイルへのアクセスを拒否する。
  • マイグレーションがあるリリース前はDBをバックアップする。

注意点

  • 無料の GitHub Pages は基本的にリポジトリを Public にして公開する。APIキー等の秘密情報は push しない。
  • 特定の人だけに見せたい場合は、認証付きのホスティングを検討する。
